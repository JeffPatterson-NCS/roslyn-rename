roslyn-rename

Semantic C# symbol rename via Roslyn. No grep. No missed references.

$ roslyn-rename --solution MyApp.slnx --old OldName --new NewName

why

AI tools that rename by grepping files miss references in generated code, hit false positives in strings and comments, and don't understand C# semantics. A method named Process appears in XML docs, string literals, log messages, and reflection calls — none of which should change.

This tool loads your solution into a Roslyn workspace and calls Renamer.RenameSymbolAsync — the same engine VS and Rider use. If the IDE would rename it, this tool renames it. If the IDE would leave it alone, this tool leaves it alone.

requirements

.NET 10 SDK or later. A .sln or .slnx solution file.

installation

$ git clone https://github.com/JeffPatterson-NCS/roslyn-rename
$ cd roslyn-rename
$ dotnet pack -o nupkg
$ dotnet tool install --global --add-source ./nupkg RoslynRename

Verify:

$ roslyn-rename --help

To update after pulling changes:

$ dotnet pack -o nupkg
$ dotnet tool update --global --add-source ./nupkg RoslynRename

usage

roslyn-rename --solution <path> --old <name> --new <name> [options]
FlagShortDescription
--solution-sPath to the .sln or .slnx file
--old-oSymbol name to rename
--new-nNew symbol name
--kind-kclass interface struct enum delegate type method property field event namespace
--dry-runPrint what would change without writing files
--allow-partialProceed even if some projects fail to load

Use --kind when multiple symbols share the same name. If the tool finds more than one match it lists them and exits — run again with --kind to narrow it down.

claude code skills

Two skill aliases ship with the repo. Run the following from inside the roslyn-rename directory:

Windows (PowerShell)

$ New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\commands"
$ Copy-Item .claude\commands\cs-ren.md "$env:USERPROFILE\.claude\commands\cs-ren.md"
$ Copy-Item .claude\commands\cs-mv.md "$env:USERPROFILE\.claude\commands\cs-mv.md"

Linux / macOS

$ mkdir -p ~/.claude/commands
$ cp .claude/commands/cs-ren.md ~/.claude/commands/cs-ren.md
$ cp .claude/commands/cs-mv.md ~/.claude/commands/cs-mv.md
/cs-ren /cs-mv

Both aliases are identical — use whichever feels natural:

/cs-ren OldName NewName
/cs-mv  OldName NewName --kind class
/cs-ren ProcessOrder HandleOrder --kind method --dry-run

By default Claude only uses the skill when you type the slash command. To make it automatic for all C# rename requests, add this to ~/.claude/CLAUDE.md:

## C# Rename
Always use `/cs-ren` for any C# symbol rename (class, method, property,
field, interface, enum). Never grep or text-search files to find references.

faq

Does Claude automatically use this when I ask to rename something?

No — not unless you tell it to. By default Claude doesn't know the tool exists and falls back to LSP lookups and file-by-file edits. Add the two lines above to ~/.claude/CLAUDE.md to make it the default for all C# rename requests.

Can I still call it explicitly without modifying CLAUDE.md?

Yes. /cs-ren OldName NewName and /cs-mv OldName NewName work at any time regardless of whether the CLAUDE.md instruction is present.

Why does it need a .sln or .slnx file?

Roslyn needs the full project graph through MSBuild to resolve cross-project references correctly. A standalone .csproj doesn't provide enough context. If you only have a single project, create a solution first:

$ dotnet new sln && dotnet sln add YourProject.csproj
What if only some projects in my solution load?

The tool exits with an error listing the failed projects rather than silently producing an incomplete rename. Fix the load errors first — usually a missing SDK or unrestored packages. If you're certain the failures don't contain references to the symbol you're renaming, pass --allow-partial to proceed anyway.
